# RAG Project - Complete Handoff

## Project Goal

Build a Retrieval-Augmented Generation (RAG) system capable of answering questions about the provided vLLM codebase.

Pipeline:

```text
Corpus
  ↓
Indexing
  ↓
Retrieval
  ↓
Qwen
  ↓
Structured Answer
```

The retrieval system is the foundation of the project. If retrieval fails, generation will also fail.

# Retrieval Method

Chosen method:

```text
BM25
```

Library:

```text
rank_bm25
```

Reason:

* Better lexical retrieval than TF-IDF.
* Includes document length normalization.
* Commonly used in search systems.
* Explicitly allowed by subject.

---

# Chunking Philosophy

Primary rule:

```text
Preserve the largest meaningful structure possible
while respecting max_chunk_size.
```

Not:

```text
Every chunk should be 2000 characters.
```

Instead:

```text
Meaningful
+
Under size limit
```

# Internal Chunk Model

Planned model:

```python
class Chunk(BaseModel):
    chunk_id: int
    file_path: str
    first_character_index: int
    last_character_index: int
    text: str
    symbol_name: str | None
    symbol_type: str | None
    language: str
```

Examples:

```text
symbol_type="class"
symbol_name="LoraManager"
```

```text
symbol_type="function"
symbol_name="load_adapter"
```

```text
symbol_type="section"
symbol_name="Loading Adapters"
```

# Python Chunking Design

Chosen approach:

```text
AST
```

Reason:

* Reliable.
* Understands Python syntax.
* Easier than regex.
* Provides structural information.

---

## AST Understanding

AST Tree Example:

```python
class LoraManager:
    VERSION = 1

    def load_adapter(self):
        pass

    def unload_adapter(self):
        pass
```

Conceptually becomes:

```text
Module
│
└── ClassDef(LoraManager)
    │
    ├── Assign(VERSION)
    │
    ├── FunctionDef(load_adapter)
    │
    └── FunctionDef(unload_adapter)
```

Important:

AST is NOT a binary tree.

Nodes can have:

```text
0 children
1 child
many children
```

---

# How AST Will Be Used

AST is used only for:

```text
Finding structure
Finding boundaries
Finding classes
Finding functions
```

Chunk text itself comes from:

```text
Original source file
```

We are NOT reconstructing code from AST.

---

# Python Chunking Hierarchy

Algorithm:

```text
Class
│
├── Fits?
│      YES -> one chunk
│
└── NO
       ↓
    Split by methods
```

```text
Function
│
├── Fits?
│      YES -> one chunk
│
└── NO
       ↓
    Split further
```

---

# Important Design Decision

If a class is:

```text
1800 chars
```

and:

```text
max_chunk_size = 2000
```

Then:

```text
ONE chunk
```

We do NOT split methods unnecessarily.

Reason:

Preserves relationships between methods and class context.

---

# Oversized Structures

Example:

```text
Function = 3500 chars
Max = 2000 chars
```

Must split.

Chosen solution:

```text
Metadata Header
+
Overlap
```

Example:

```text
Function: load_adapter
Class: LoraManager

<code>
```

and:

```text
100 character overlap
```

Current plan:

```text
overlap_size configurable
```

Not hardcoded.

---

# Character Offsets

Subject requires:

```text
file_path
first_character_index
last_character_index
```

AST provides:

```text
lineno
end_lineno
```

Solution:

```text
Source File
    ↓
Build line → character lookup table
    ↓
Convert AST line numbers
    ↓
Character offsets
```

Example:

```text
abc\n
12345\n
hello\n
```

Line 3 starts at:

```text
10
```

---

# Markdown Chunking Design

Strategy:

```text
Heading
+
Associated Content
```

Keep sections together whenever possible.

Example:

```markdown
## Loading adapters

Use POST /v1/load_lora_adapter
```

Heading remains inside chunk.

Reason:

Headings carry strong retrieval information.

---

# Tokenization Design

Current plan:

Identifiers contribute multiple searchable terms.

Example:

```text
load_lora_adapter
```

Produces:

```text
load_lora_adapter
load
lora
adapter
```

Benefits:

Supports both:

```text
load_lora_adapter
```

and:

```text
load adapter
```

queries.

Implementation still undecided.
